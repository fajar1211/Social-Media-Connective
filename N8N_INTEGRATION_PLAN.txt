## PHASE 1: WEBHOOK INTEGRATION (Hari 2-3)
============================================================

Task 1: Buat n8n Webhook Workflow
----------------------------------
  Workflow: "Publish Content"

  Nodes:
    1. Webhook Trigger
       - Method: POST
       - Path: /publish
       - Auth: Header (X-Webhook-Secret)

    2. HTTP Request (Validate)
       - Check secret header
       - Validate content ID exists

    3. Supabase (Read Content)
       - Operation: Get Row
       - Table: content
       - ID: {{ $json.contentId }}

    4. Switch (Platform Router)
       - Facebook -> Facebook Post
       - Instagram -> Instagram Post
       - LinkedIn -> LinkedIn Post
       - X/Twitter -> X Post

    5. Facebook Post Node
       - Page ID: {{ $json.pageId }}
       - Message: {{ $json.caption }}
       - Access Token: {{ $json.accessToken }}

    6. Supabase (Update Status)
       - Table: content
       - ID: {{ $json.contentId }}
       - Status: Published

  Webhook URL: http://localhost:5678/webhook/publish

Task 2: Modifikasi App API Routes
-----------------------------------
  File: src/routes/api.facebook.post.tsx

  Sebelum:
    - Direct fetch ke Facebook Graph API
    - Menggunakan pageAccessToken dari request body

  Sesudah:
    - Panggil n8n webhook
    - Kirim content ID + metadata
    - n8n handle posting

  Contoh kode:
    const N8N_WEBHOOK_URL = process.env.N8N_WEBHOOK_URL || "http://localhost:5678/webhook/publish";
    const N8N_WEBHOOK_SECRET = process.env.N8N_WEBHOOK_SECRET;

    const response = await fetch(N8N_WEBHOOK_URL, {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        "X-Webhook-Secret": N8N_WEBHOOK_SECRET,
      },
      body: JSON.stringify({
        contentId: contentId,
        clientId: clientId,
        platform: platform,
        pageId: pageId,
      }),
    });

Task 3: Update Environment Variables
--------------------------------------
  File: .env

  Tambah:
    N8N_WEBHOOK_URL=http://localhost:5678/webhook/publish
    N8N_WEBHOOK_SECRET=your-secret-here

## PHASE 2: CONTENT SYNC (Hari 4-5)
============================================================

Task 1: Supabase Read Workflow
-------------------------------
  Workflow: "Sync Content"

  Nodes:
    1. Schedule Trigger
       - Every 1 hour

    2. Supabase (Read Approved)
       - Table: content
       - Filter: status = "Approved"

    3. Loop Over Items
       - For each approved content

    4. Switch (Platform)
       - Route to correct publisher

    5. Facebook Publisher
       - Get page access token from social_connections
       - Post to Facebook

    6. Instagram Publisher
       - Get business account token
       - Create media container
       - Publish to Instagram

    7. LinkedIn Publisher
       - Get LinkedIn token
       - Post to LinkedIn

    8. X/Twitter Publisher
       - Get X API token
       - Post tweet

    9. Supabase (Update Status)
       - Set status to "Published"

Task 2: Multi-Platform Posting
--------------------------------
  Workflow: "Multi-Platform Publish"

  Nodes:
    1. Webhook Trigger
       - Receives content ID

    2. Supabase (Get Content)
       - Read content details

    3. Supabase (Get Client Platforms)
       - Read social_connections for client

    4. Split by Platform
       - Facebook posts
       - Instagram posts
       - LinkedIn posts
       - X posts

    5. Parallel Execution
       - Post to all platforms simultaneously

    6. Aggregate Results
       - Collect all platform responses

    7. Supabase (Update with Results)
       - Store platform-specific post IDs

Task 3: Handle Media Upload
-----------------------------
  Workflow: "Upload Media"

  Nodes:
    1. Webhook Trigger
       - Receives: media URL, platform, access token

    2. HTTP Request (Download)
       - Download image/video from URL

    3. Switch (Platform Format)
       - Facebook: Direct upload
       - Instagram: Container creation
       - LinkedIn: Upload media

    4. Upload to Platform
       - Handle platform-specific requirements

    5. Return Media ID
       - For use in post creation

## PHASE 3: SCHEDULING (Hari 6-7)
============================================================

Task 1: Cron Trigger Workflow
-------------------------------
  Workflow: "Scheduled Publisher"

  Nodes:
    1. Schedule Trigger
       - Every 5 minutes

    2. Supabase (Read Scheduled)
       - Table: content
       - Filter: status = "Approved"
       - Filter: scheduled_date <= NOW()
       - Filter: scheduled_time <= current time

    3. Loop Over Items
       - For each scheduled content

    4. Check Time Window
       - Verify it's time to publish

    5. Publish Content
       - Call publish workflow

    6. Supabase (Update Status)
       - Set status to "Published"
       - Clear scheduled fields

Task 2: Timezone Handling
---------------------------
  Workflow: "Timezone Converter"

  Nodes:
    1. Input Node
       - scheduled_date
       - scheduled_time
       - timezone

    2. Code Node (Convert)
       const scheduledDateTime = new Date(`${scheduled_date}T${scheduled_time}`);
       const userTimezone = timezone || 'Asia/Jakarta';
       const utcTime = scheduledDateTime.toLocaleString("en-US", { timeZone: "UTC" });

    3. Compare with Current Time
       - If utcTime <= NOW() then publish

Task 3: Status Tracking
--------------------------
  Database Fields:
    - scheduled_date: DATE
    - scheduled_time: TEXT
    - timezone: TEXT
    - published_at: TIMESTAMPTZ (add new)
    - platform_post_ids: JSONB (add new)

  Migration:
    ALTER TABLE content ADD COLUMN published_at TIMESTAMPTZ;
    ALTER TABLE content ADD COLUMN platform_post_ids JSONB DEFAULT '{}'::jsonb;

## DATABASE MIGRATIONS
============================================================

-- Migration: Add n8n support fields
-- File: supabase/migrations/20260904000000_add_n8n_support.sql

-- Add published_at timestamp
ALTER TABLE content ADD COLUMN published_at TIMESTAMPTZ;

-- Add platform-specific post IDs
ALTER TABLE content ADD COLUMN platform_post_ids JSONB DEFAULT '{}'::jsonb;

-- Add n8n integration settings to clients
ALTER TABLE clients ADD COLUMN n8n_webhook_url TEXT;
ALTER TABLE clients ADD COLUMN n8n_auto_publish BOOLEAN DEFAULT false;

-- Create publish history table
CREATE TABLE publish_history (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  content_id UUID REFERENCES content(id) ON DELETE CASCADE,
  platform TEXT NOT NULL,
  status TEXT NOT NULL, -- 'success', 'failed', 'pending'
  platform_post_id TEXT,
  error_message TEXT,
  published_at TIMESTAMPTZ DEFAULT NOW(),
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Index for faster queries
CREATE INDEX idx_publish_history_content_id ON publish_history(content_id);
CREATE INDEX idx_publish_history_status ON publish_history(status);

-- RLS policies
ALTER TABLE publish_history ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Admin full access on publish_history" ON publish_history
  FOR ALL USING (
    EXISTS (SELECT 1 FROM profiles WHERE id = auth.uid() AND role = 'admin')
  );

CREATE POLICY "Client can view own publish_history" ON publish_history
  FOR SELECT USING (
    content_id IN (
      SELECT id FROM content WHERE client_id = (
        SELECT client_id FROM profiles WHERE id = auth.uid()
      )
    )
  );

## SECURITY CONSIDERATIONS
============================================================

1. Webhook Authentication
   - Use secret header (X-Webhook-Secret)
   - Validate on n8n side
   - Rotate secrets periodically

2. Token Storage
   - Store in Supabase (social_connections table)
   - Never expose in frontend
   - Use Supabase RLS for access control

3. Rate Limiting
   - Facebook: 200 calls/hour per user
   - Instagram: 200 calls/hour per user
   - LinkedIn: 100 calls/day
   - X/Twitter: 300 tweets/3 hours

4. Error Handling
   - Retry failed posts (max 3 attempts)
   - Log all errors to publish_history
   - Notify admin on critical failures
